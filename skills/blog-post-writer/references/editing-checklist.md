# Editing Checklist

Run top to bottom on a finished draft. Editing is where good posts become great. Read aloud at least once.

## Structure pass
- [ ] The single takeaway is stated in one sentence somewhere obvious.
- [ ] The hook creates tension or promises payoff in the first 2 sentences.
- [ ] Each H2 makes one point; reading only the H2s tells the story.
- [ ] Every section leads with its point, then supports it.
- [ ] The conclusion gives an action or crisp summary — not "Hope this helps."

## Evidence pass
- [ ] Every abstract claim has a concrete example, number, or code.
- [ ] Vague adjectives replaced with specifics ("fast" → a measurement).
- [ ] All code blocks are minimal, correct, language-tagged, and tested.
- [ ] Expected output / result is shown for commands and snippets.
- [ ] Claims are accurate; no overstated benchmarks.

## Line pass
- [ ] Active voice and "you" where natural.
- [ ] Paragraphs are 2-4 sentences; break up walls of text.
- [ ] Sentence length varies; key points land in short sentences.
- [ ] Filler removed: "very, really, just, basically, actually, in order to, the fact that."
- [ ] Hedging removed where you can commit: "I think maybe it could possibly…".
- [ ] No throat-clearing intro left ("In today's world…").
- [ ] Jargon defined on first use for the target reader.
- [ ] Transitions/signposts guide the skim (First, Next, The catch).

## Polish pass
- [ ] Title is specific and benefit-driven; 3+ options were considered.
- [ ] Meta description written (150-160 chars).
- [ ] Headings, lists, and whitespace make it scannable.
- [ ] Spelling/grammar clean; product and tech names capitalized correctly.
- [ ] Links work and point where claimed.
- [ ] Cut at least 10% of the word count.

## The final gut check
Read only the first paragraph and the last paragraph. Do they, together, make someone want the middle? If not, fix the bookends first.
