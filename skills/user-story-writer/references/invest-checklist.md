# INVEST Checklist

A good user story is **INVEST**:

| Letter | Property | Test |
| --- | --- | --- |
| **I** | Independent | Can it be built and shipped without depending on another unfinished story? Reorderable in the backlog? |
| **N** | Negotiable | Is it a conversation starter, not a rigid contract? Does it avoid prescribing implementation? |
| **V** | Valuable | Does it deliver observable value to a user or buyer? Can you name the benefit? |
| **E** | Estimable | Does the team understand it well enough to size it? If not, it's too vague or too big. |
| **S** | Small | Does it fit comfortably within one sprint (ideally a few days)? |
| **T** | Testable | Can you write pass/fail acceptance criteria? "Fast", "nice", "intuitive" are not testable. |

## Quick gate

- [ ] Single role, single outcome
- [ ] "so that <benefit>" names real value
- [ ] No "and" hiding a second story
- [ ] At least 1 happy-path + 1 edge/negative scenario
- [ ] Every criterion is independently verifiable
- [ ] Team could estimate it today

If any box is unchecked, sharpen or split before committing the story.
