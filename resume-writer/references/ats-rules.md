# ATS-Friendliness Rules

Applicant Tracking Systems parse your resume into fields before a human sees it. A pretty resume that parses wrong gets auto-rejected.

## Do
- Use **standard section headings**: Summary, Experience, Education, Skills, Certifications.
- Use a **single-column, top-to-bottom** layout for the version you upload.
- Use **real bullet characters** (`•` or `-`) and standard fonts (Arial, Calibri, Garamond, Helvetica).
- Save as a **text-based PDF** or `.docx` (never a scanned image / flattened PDF).
- Spell out **then** abbreviate: "Search Engine Optimization (SEO)" so both forms match.
- Mirror the **exact keywords** from the job description (titles, tools, skills).
- Put dates in a consistent `MMM YYYY – MMM YYYY` format.

## Avoid
- **Tables, columns, text boxes** — parsers read them out of order or drop them.
- **Headers/footers** for critical info (name, contact) — often ignored by parsers.
- **Images, logos, icons, photos, charts** — invisible or garbled to ATS.
- **Fancy/decorative fonts** and uncommon symbols.
- **Stuffing white/hidden keywords** — modern ATS and recruiters catch it; it's an instant reject.

## Keyword matching
ATS scores partly on literal term overlap with the JD. If the posting says "stakeholder management," use that phrase — not "managed relationships." Match nouns (skills, tools, certifications) exactly; vary verbs freely.

## Two-version strategy
Keep a clean **ATS version** (single column, plain) for online applications, and optionally a lightly **designed version** (PDF) to hand directly to a human. Never submit only the designed one to a portal.
